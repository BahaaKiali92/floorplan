## Project structure

Structure of the main branch (regenerated by CI after every merge to main; never edit it by hand):

@docs/PROJECT_MAP.md

What the current branch changed compared with main is in `.project-map/BRANCH_CHANGES.md` (local, never committed).
A short summary of it is added automatically at the start of every session. Refresh it with
`node scripts/project-map/generate-map.mjs`.

- Before creating a class, find the right package in the map and follow the package purposes and rules there.
- Before changing a controller or service, check "Dependencies between areas" and "HTTP endpoints and listeners" to see
  what else could be affected.
- Move classes and packages with `node scripts/project-map/move-cli.mjs <source> <target-folder>` (dry run, paths relative
  to the map root), then add `--apply`. It changes the package declarations, rewrites every import (also for classes
  that were in the same package), moves the matching tests and refreshes the local map. Read its warnings: strings,
  `application.yml` and XML are not rewritten.
- After creating, moving or deleting classes, run `node scripts/project-map/generate-map.mjs` (local map and branch report only).
- Do not run `generate-map.mjs --main` and do not edit `docs/PROJECT_MAP.md`: CI regenerates it after merges to main.
- Before finishing a task, run your normal checks (compile, tests) as usual, and **in addition**
  `node scripts/project-map/generate-map.mjs --check`, which must pass. It fails only on rule issues this branch
  introduced. Fix them by moving the class or changing the dependency; do not change a rule unless asked.
  The check looks at structure only, never at code.
