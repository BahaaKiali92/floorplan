## Project structure

Structure of the main branch (regenerated by CI after every merge to main; never edit it by hand):

@docs/PROJECT_MAP.md

What the current branch changed compared with main is in `.project-map/BRANCH_CHANGES.md` (local, never committed).
A short summary of it is added automatically at the start of every session. Refresh it with `npm run map`.

- Before creating a file, find the right folder in the map and follow the folder purposes and rules there.
- Before changing a component or service, check "Dependencies between areas" to see what else could be affected.
- Move files and folders with `node scripts/project-map/move-cli.mjs <source> <target-folder>` (dry run), then add `--apply`.
  It moves companions (.html, .scss, .spec.ts), rewrites every import and refreshes the local map.
- After creating, moving or deleting files, run `npm run map` (local map and branch report only).
- Do not run `npm run map:main` and do not edit `docs/PROJECT_MAP.md`: CI regenerates it after merges to main.
- Before finishing a task, run your normal checks (type check, tests, lint) as usual, and **in addition**
  `npm run map:check`, which must pass. It fails only on rule issues this branch introduced. Fix them by moving the
  file or changing the import; do not change a rule unless asked. `map:check` checks structure only, never code.
